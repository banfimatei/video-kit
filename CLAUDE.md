# video-kit — Claude playbook

Remotion 4.0.529 toolkit (repo root, `@banfimatei/video-kit`) plus a render
service (`service/`, npm workspace, deployed on Railway). Usage and API: [README.md](README.md).

## Layout

- `src/` — the library. Entries: `.` (runs inside compositions: `Sfx`,
  `SfxCues`, `VoiceTrack`, `resolveSound`, plus core), `./core` (schemas and
  `fitScenesToVoice`, no assets, safe in Node), `./node` (TTS,
  `renderComposition`, site packing, CLI), `./client` (service client, fetch
  only). The root entry imports `.wav` files that only a bundler understands,
  so Node code must import `./core` or `./node`, never `.`.
- `assets/sfx/` — house cues, generated by `scripts/make-sfx.ts` (deterministic).
- `service/src/` — Hono API (`server.ts`), job store and queue (`jobs.ts`, JSON
  files, atomic writes), runner and webhooks (`runner.ts`), request checks
  (`props.ts`, `net.ts`), sites, retention.
- `service/remotion/` — built-in templates, bundled to `service/bundle` at build time.

## Rules

- Load the `remotion-best-practices` skill before writing Remotion code; add
  `@remotion/*` packages at the exact same version as `remotion`.
- The service and library share one copy of Remotion and React through the
  workspace. Don't add them to the service's own nested node_modules.
- Nothing in the request path may throw from a stream callback or leave a
  promise unhandled: either takes the whole process down. See the tar filter
  in `sites.ts` and `JobStore.persist`.
- Voice clips reach the headless Chrome over `http://127.0.0.1:$PORT/internal/voice/…`,
  which answers loopback only. Render files are served only by signed link or bearer key.
- A render captures its site's version directory when submitted; redeploying a
  site must never change files under a running render.
- Templates validate props in Node (`BUILTIN_TEMPLATES[id].prepare`, via
  `service/src/props.ts`) so bad input is a 400, not a failed job. The job
  stores the prepared props, and drops them once it is terminal.
- Remotion merges a composition's `defaultProps` under every render's props,
  key by key, and JSON drops `undefined`. So `prepareStoryProps` sets every
  key of `STORY_SAMPLE_PROPS` explicitly (`null`, `""`, `{}`), or the sample
  brand and footer end up in clients' videos. Keep that true for new keys and
  new templates.
- Anything a template makes headless Chrome fetch goes through its `urls()`,
  so the service can refuse private hosts. The service owns `voiceover`; one
  sent by a client is dropped. Webhooks go through `net.ts` (public hosts
  only, lookup pinned at connect).
- Records keyed by ids from props are null-prototype and read with `own()`
  (a scene id like `constructor` must be an ordinary key).
- Shutdown: Remotion's own SIGTERM listener kills every open browser, so the
  image runs node under `dumb-init --rewrite 15:12` and the service drains on
  SIGUSR2. During the drain the HTTP server must keep listening: renders
  fetch their voice clips from it. Jobs still `queued` at a stop are re-queued
  at boot; `running` ones are failed with `RESTARTED` and get their webhook.
- Webhooks are at least once: the `webhookPending` flag is persisted with
  the terminal status and cleared only after delivery or giving up.
- Story type is fitted by estimate in `templates/story/layout.ts`. When you
  change type sizes, faces or chrome, render stills of the longest allowed
  text at all four aspects and look at them.

## Verify

```bash
npm run typecheck && npm test
cd service && npm run build && npm run bundle
RENDER_API_KEY=dev-key-0123456789ab DATA_DIR=/tmp/vk node dist/src/index.js &
VIDEO_KIT_URL=http://localhost:8080 VIDEO_KIT_API_KEY=dev-key-0123456789ab SMOKE_TTS=espeak npm run smoke
```

In a Claude Code cloud session: set
`REMOTION_BROWSER_EXECUTABLE=/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell`
(remotion.media is blocked) and `apt-get install espeak-ng` for the offline voice.

## Deploys

Railway deploys `main` on push (only paths in the service's watch list; see
README). That needs Railway's GitHub app to have access to this repo; if a
push doesn't deploy, check that first. OpenRouter voices need
`OPENROUTER_API_KEY` on the service.
